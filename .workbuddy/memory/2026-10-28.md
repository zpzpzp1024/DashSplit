## 0.1.22 提交审查（CarPlay 连接闪灭问题）

- 审查对象：4c3179b（0.1.22，birth<20s 跳过 preempt stand-down）。
- 关键证据（packages/存档/DashSplit.log，0.1.20/0.1.21 代码）：
  - 两份存档日志中 `preempt[` 触发次数为 0 —— SBMainDisplaySceneManager
    `_scene:didUpdateClientSettingsWithDiff:` 钩子从未见到杀死性 diff。
  - 真实故障链：host → live confirmed（约2s）→ 6~8s 后 foreground=No diff 经
    未挂钩路径到达 Live controller → NSInternalInconsistencyException →
    throw hook "passing through" + resync mode→0（消失）→ 未捕获异常 →
    SpringBoard respring → 重建（重现）→ 循环。"重现"实为崩溃后重建。
- reflog：0.1.21 之后曾有 0.1.23~0.1.26 实验线（含 `_updateStateForScene:withSettings:`
  backstop 钩子），因 stand-down 只做单个 slot 导致 signal 5 无限 respring，
  于 10-28 07:47 被 reset 丢弃；随后提交极简 0.1.22。
  DashSplit-2.log（0.1.24 构建）证明 backstop 钩子能看到真 diff。
- 结论：0.1.22 修改的 preempt 路径在故障场景下从未执行，预期无法修复；
  且 20s 宽限期内 preempt 保护被禁用，构成理论崩溃窗口；魔数 20 在
  812 行与 1531 行重复。
- 建议方向：挂钩 SBSceneManager 无下划线变体或 `_updateStateForScene:withSettings:`
  且保留 stand-down-ALL；更优方案是用 `_scene:interceptUpdateWithNewSettings:`
  拦截并改写 hosted scene 的 foreground=No；用 sceneIdentifier 精确匹配 diff→slot。

## 问题 2 落地：解锁自动隐藏（0.1.27，提交 b1d8b2f）

- 用户提供关键实测证据：三分屏隐藏（mode 0）状态下，手机开任何 app/设置
  都不 respring → "解锁即自动降级"可根治问题 2。
- 需求确认：解锁 → 自动隐藏（等价手动点 ✕）；锁屏 → 不做任何事（不自动
  展示）；恢复永远靠手动点按钮。
- 实现：订阅系统锁屏 Darwin 通知 `com.apple.springboard.lockstate`
  （notify_register_dispatch + notify_get_state 判定 0=解锁/1=锁定，
  纯事件订阅非 hook），解锁时执行与按钮隐藏分支完全相同的降级序列
  （提取为 HidePanesAndStandDown，按钮与监听器共用）。
- 边界处理：gAwaitingStart 时解锁 → 取消 pending 延迟启动并收回窗格；
  已隐藏/测试模式/无窗口 → 不动作；锁屏事件 → 仅记日志。
- 版本跳到 0.1.27：避开旧循环重启实验线占用的 0.1.24~0.1.26，防止装机混淆。
- 仍未编译验证（本地无 Theos）；上车实测点：连接后点 ▶ 出画面 → 解锁手机
  → 车机自动隐藏且手机开设置不 respring → 点按钮恢复。
